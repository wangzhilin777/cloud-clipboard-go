# Android Sync Client

该目录是“安卓同步客户端”，与仓库原有的 `android/` 服务器 APK 工程分离。

安卓客户端用于接入仓库中的新同步协议，当前阶段目标是：

* Android / Web / Windows 三端纯文本自动同步
* Android 接收图片 / 文件通知
* 用户确认后才下载到本地缓存
* 下载完成后在 App 内接收页处理，不自动写入系统剪贴板

## 构建

```bash
./gradlew assembleDebug
```

默认 Debug APK 输出位置：

```text
app/build/outputs/apk/debug/app-debug.apk
```

## 图标资源

安卓启动图标当前采用自适应图标：

* 前景输出：`app/src/main/res/drawable-nodpi/ic_launcher_foreground_image.png`
* 原始源图：`app/src/main/res/drawable-nodpi/icon-sources/launcher-source.png`
* 当前安全区缩放比例固定为 `0.68`

如果后面要换图标，不要直接手改输出图，按下面方式重新生成：

```bash
python scripts/generate_launcher_icon.py
```

生成后再重新构建 APK。

## 配置

首次打开 App 后填写：

* 服务端地址：例如 `http://192.168.1.10:9501`
* 如果现在是 Windows 这台机器在跑 Go 服务，安卓里必须填 `http://Windows局域网IP:9501`，不要填 `127.0.0.1`
* 房间：可留空
* 房间密码：如果房间设置了房间密码，就填房间密码；否则这里填写全局密码
* 设备名称：显示在网页端设备列表中

保存后点击“启动同步”。

## 当前行为

### 文本

* 本地文本剪贴板变化后会自动上报
* 前台服务会结合系统剪贴板回调和轻量轮询兜底，尽量降低部分 ROM 漏回调带来的丢同步概率
* 收到远端文本后会自动写入安卓系统剪贴板
* 未通过房间密码时无法接入同步房间
* 未信任设备只保活连接，不发送文本
* 服务端重连后会尝试恢复最近一条文本到安卓系统剪贴板
* 当前对“短时间内重复触发的同一段文本”会做本地去重，避免一次复制被重复上报
* 运行页现在会先显示“后台复制就绪度”摘要，再显示“后台复制诊断”卡片，可更快判断当前模式在真机后台复制场景下大致可不可用、主要风险是什么、下一步该补哪项设置

### 图片 / 文件

* 收到 `payloadNotice` 后，优先走悬浮确认；未开启悬浮窗权限时退回系统通知
* 当前可由网页端上传完成后主动触发该通知
* 用户点击“确认接收”后才开始下载
* 悬浮确认的“稍后处理”时长现在可配置；进入冷却后会避免重连或恢复时立刻重复弹出
* 下载目标是应用私有缓存目录，不会自动落到公共 Download 目录
* 下载完成后可在“接收页”中进行：
  * 图片预览
  * 打开文件
  * 分享文件
  * 另存为
  * 标记已处理
* 在接收页完成打开、分享、另存或标记已处理后，会自动切到下一条内容，减少重复返回操作
* 接收页支持按全部 / 待处理 / 已处理 / 稍后提醒快速筛选，也支持一键清理已处理内容和恢复稍后提醒
* 主界面的“接收与缓存”摘要会直接显示待处理、已处理、稍后提醒、已缓存和当前缓存占用

## 权限与后台建议

* 权限页会统一展示通知、悬浮窗、无障碍、电池优化、Shizuku 状态
* 当前已提供厂商后台保活入口，优先覆盖：
  * 澎湃 / MIUI
  * 华为 / 荣耀
  * OPPO / OnePlus / realme
  * vivo / iQOO
  * 三星
* 如果你在高版本 Android 或国产 ROM 上遇到“前台正常、后台复制不回传”，建议优先看：
  * 运行页的“后台复制就绪度”摘要
  * 运行页的“后台复制诊断”
  * 权限页的厂商后台保活建议
  * 无障碍增强模式是否已实际开启

## 缓存策略

* 默认缓存保留 24 小时
* 清理触发时机：
  * App 启动
  * App 回到前台
  * 同步服务启动
  * 开始新的 payload 下载前
* “已处理”仅表示用户已经手动处理过，不会立刻删除缓存

## 限制

* 当前不做第三方输入框自动粘贴
* 当前不做图片自动写入系统剪贴板
* 当前非文本接收流程只在 Android 端实现
* Android 10+ 及部分 ROM 会限制后台应用读取系统剪贴板
* 当前前台服务模式是一期开箱可用主通道
* 当前无障碍模式已接入入口、校验、恢复流程，以及界面交互触发的剪贴板补检查，但后台增强细节仍会继续补强
* 当前 Shizuku 模式仅完成入口与状态探测，真实增强链路尚未接入，现阶段不开放启动
